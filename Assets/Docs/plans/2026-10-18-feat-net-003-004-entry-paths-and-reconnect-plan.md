# Networking entry paths, package migration and seat reconnect (NET-003, MAINT-003, NET-004)

**Authored context:** Written and implemented in the same pass on 2026-10-18. The user approved:
- migrating Lobby and Relay to Multiplayer Services;
- host-issued seat secrets for reconnecting;
- implementing directly.

Live Lobby/Relay checks wait for the user's permission. The user confirmed the project never used Steam's relay: git history shows Unity Relay and Lobby since 2023-08. Evidence: [verification report](../GAMEPLAY_INTEGRATION_VERIFICATION.md#net-003-maint-003-net-004-2026-10-18). Entry paths: [NETWORKING_ENTRY_PATHS.md](../NETWORKING_ENTRY_PATHS.md). Lessons: [netcode learning guide](../NETCODE_LEARNING_GUIDE.md).

## Decisions

- **Multiplayer Services 2.3.3.** It is the newest release at least two weeks old (2026-09-15); 2.4.x was days old. The migration was developed in the isolated project and applied to the working project in one step, because the user's Editor had the project open.
- **The flow stays the same.** It is still: Start → anonymous sign-in → quick-join or create a lobby → Relay → host/client.
- **The RPC attribute migration is part of this change.** Optional UTF-8 payloads stay deferred, because bandwidth is not a problem (MAINT-003 note).
- **Seat secrets:**
  - Each seat's secret is 128 random bits, sent only in that seat's own projection and kept in memory by `ClientSession`.
  - It is compared in constant time and rotated after each successful reclaim.
  - It does not survive an app restart; persistent recovery is a separate scope decision.
- **No new player states.** The existing suspended state already offers Resume and New Match. Its Retry action now reconnects when the connection is gone, through `GameSession`. A strict state-map comparison shows no added or removed states or transitions.

## Units

### U1. Package and API migration (NET-003, MAINT-003)

- **Packages:** in `Packages/manifest.json`, Lobby 1.1.0 and Relay 1.0.5 were replaced by Multiplayer Services 2.3.3. `packages-lock.json` was regenerated by Unity in the isolated project with an identical dependency set.
- **`SimpleMatchmaking`:**
  - Uses `LobbyService.Instance` and DTLS Relay through `ToRelayServerData("dtls")`.
  - Caps the lobby at 8 players and the allocation at 7 connections.
  - Awaits and logs service calls; only "no open lobbies" falls through to creating a lobby.
  - Guards against a second click and allows retry.
  - Adds `--ugs-profile <name>` (separate anonymous identities on one machine) and `RejoinRelay()` for reconnecting.
- **`GameSession`:** `[Rpc(SendTo.Server, InvokePermission = RpcInvokePermission.Everyone)]` and `[Rpc(SendTo.SpecifiedInParams)]` with `RpcTarget.Single(id, RpcTargetUse.Temp)`, replacing the obsolete forms.
- **Unity find APIs:** `FindObjectOfType`, `FindFirstObjectByType` and `FindObjectsSortMode` were replaced in production and harness code.
- **Entry paths documented:** supported paths, developer tools, legacy code and failure behavior are in `NETWORKING_ENTRY_PATHS.md`.

### U2. Seat reclaim (NET-004)

- **`SeatRegistry`:** secrets, `TryRebind` (checks wrong match, unknown seat, wrong secret, seat still connected, already seated; a repeated claim from the same connection is harmless) and rotation.
- **Coordinator:** `Reclaim` and a live `Participants` list. Each projection carries only its own seat's secret.
- **Wire:** `ProjectionPacket.SeatSecret` and `MissingSeats`, plus `ReclaimRequest` with its codec support. `WireCodec.Version` went to 2 and the fixtures were regenerated with `JsonUtility`.
- **`ClientSession`:** `Credential`, which survives `BeginConnection`, and `MissingSeats`. Only packets at least as new as the current view update them.
- **`GameSession`:**
  - `OnNetworkSpawn` reclaims when the client has a credential, resubmitting any unanswered request.
  - `ReclaimSeatServerRpc` sends no projection unless the claim succeeds.
  - The host tracks departed transports, and every projection reports the missing seats.
  - Retry or sync while disconnected reconnects: Relay through `SimpleMatchmaking`, otherwise the saved address.
  - Resume requires every seat to be connected.
- **`InputManager`:** shows "waiting for Player N to reconnect", "everyone is back", and "Disconnected · press Retry". Resume is enabled for the host only when no seat is missing.

## Outcome

- **Console `ReconnectChecks`, 52 assertions:**
  - Secrets are private, distinct and 128-bit.
  - Disconnecting during an action, whether the command or its answer was lost, never applies twice.
  - Impersonation is rejected: wrong or truncated secret, wrong match, unknown seat, a seat still connected, a second seat. A failed claim reveals no view.
  - Repeated attempts are safe: the old secret cannot be replayed, a repeated claim is harmless, and a second drop also recovers.
  - Settings are preserved, and the old transport loses its voice.
- **Real transport, CLI `--reconnect`:**
  - The client drops while a move is in flight and reconnects through the Retry path with a new transport ID. It keeps its seat and its secret rotates.
  - A forged claim over a real RPC is refused.
  - The host sees "Player 2 missing", then "everyone back", resumes, and the match finishes all 13 rounds.
- **All other CLI scenarios and console suites still pass**, and mutation (removing the secret check) is caught.
- **Defined behavior found:** a request that never reached the host is resubmitted while the match is suspended, so it is rejected (`Suspended`) and is never applied later; the player acts again after resuming. A request that did arrive replays its cached outcome.

## Not covered

- **Live Lobby/Relay:** the online path and `RejoinRelay` need `run_players.py --live` and the user's permission. NET-003 stays open until then.
- **Visual review:** a person has not looked at the reconnect status text.
- **Host loss:** host migration and reconnecting after the host itself is lost are out of scope.
- **Restart recovery:** recovery after an app restart is out of scope (secrets are in memory only).
- **Console only:** an answer lost after a request was applied, recovered by reconnecting, is covered in the console; over real transport the in-flight request had not reached the host.
